# 统一媒体 v1 实施与验收记录

日期：2026-10-30。基线：`9e69b7674d491d3b3a8b71614358b0d29d765496`。这是候选实现的本地验收记录，交付目标为 Draft PR，不代表合并、部署或生产版本变化。真实响应、token、签名 URL、原始页面和完整日志保存在被忽略的本地目录，不进入公共仓库。

## 本轮实现

- 九平台由后端注册表统一分发，公开 `/api/parse`、`/api/resolve`、`/api/platforms` 使用 v1 合同；旧入口不再双返回旧格式。
- 所有 item 具有统一后端计算的 default；保留 variants、等价 sources、来源身份、时效和需处理的更高画质引用。微博签名后重新计算投影，不延长上游已知有效期。
- 前端按通用媒体能力消费；删除平台专属字段归一化，显式选择不被默认覆盖。结果变化不修改已建立的下载计划。
- DASH/mux/remux 只建模和提示，不执行合流，不把裸轨当完整文件。待解析 variant 保留原因，无地址和虚构规格。
- 保留已确认布局；PR #7 的下载核心、公开 Worker 和 bridge 没有行为改动。新增的消费层把完整文件交给原有原生/SW/Blob 模块。

## 抖音裸轨问题及修正

真实码率列表中的一个 2160×3840 HEVC 候选，实际 ffprobe 仅发现视频轨，文件为 23,351,671 字节、约 67.117 秒。这证明“码率列表中存在 URL”不能直接等同于完整视频。

随后在同样本原始详情中确认，19 个码率表示包含 10 个 `format=mp4` 和 9 个 `format=dash`；后者有明确音频文件 ID，可与音频表示匹配。实现按明确格式和音频 ID 建模，不依赖 URL 中含 `dash` 或 `hvc1` 来猜。缺匹配音轨时保留 deferred 原因。

修正后再次通过当前 PHP API 请求同一输入，得到 **11 个 file + 9 个 mux**（含原始入口候选），默认仍指向完整 2160×3840 文件；独立结构和语义校验通过。9 个 mux 当前明确暂不支持下载。本次不将该样本计为浏览器完整保存验收。

## 小红书 4K 边界

按用户实施阶段决定，本 PR 不加入 Python/curl_cffi 运行依赖，也不进行 Go 重写。schema 预留 deferred variant；它不意味着当前 PHP 已取得可下载的 4K。

历史报告、当前 PHP 页面失败、隔离 curl_cffi 取得 SSR、SSR 回放后的 PHP 实测 **3840×2160 H.264 MOV / 3,425,556,989 字节**、浏览器未完整保存，分别记录在 [传输对照](research/xhs-4k-transport-comparison-2026-10-30.md)。后续 Go 验收必须从有效分享 token、无 Cookie 的真实请求开始，不能以回放、上传尺寸或 720p 回退替代。

## 实际保存与 PR #7 状态观察

受控文件是本地产生的 640×360、带音频 MP4，填充至 8,388,608 字节，非真实平台文件。经独立媒体 origin 向浏览器流式交付，限速便于观察刷新行为。

两个实际保存文件 SHA-256 均为：

```text
b5f2fdfc7ec45d8a4ee0343f42efefd3c1ce19bbf939bb746a734adc489c684e
```

- **不刷新对照**：完整保存，页面最终显示完成。
- **下载中刷新**：刷新后原任务显示约 41% 并继续传输；服务端日志只有一次完整正式传输，文件大小/哈希正确。但最终页面显示“连接中断 / 原下载任务已失效”，因此刷新恢复只能记为传输和文件完整性通过，终态显示未通过。
- **原生附件**：符合命名/附件响应条件时页面显示“已交给浏览器”；本次没有找到对应保存文件，不能宣称保存通过。工具被浏览器安全策略禁止访问内部下载管理页，未绕过限制或修改安全设置。

只读核对发现 PR #7 Worker 的任务与终态历史仅保存在执行上下文的内存 Map。隔离测试证明重新初始化同一 Worker 脚本后历史查询为空，前端会显示连接中断；另一待核实点是浏览器按 Content-Length 保存完成与 Worker 读取 EOF 的时序。本次没有证据唯一确定实际浏览器属于哪一种情况，不能把假设写成已确认根因。

本 PR 不通过改写传输核心、按字节数硬判成功或强制激活 Worker 来掩盖状态缺口。Worker 升级/长期传输的历史 PR #7 证据仍保留在 [下载说明](DOWNLOADS.md)，本轮没有重新执行真实 Worker 升级对照。关闭全部页面、锁屏、系统挂起和 iPhone Safari/微信完整保存仍需各自验收。

## 自查修正

审查采用最小反例，已修正并复验：来源/版本 ID 不能依赖数组下标；微博签名不能续活过期媒体；B站音频备选不能误当同时必需的多音轨；明确 `.mpd` 清单必须建模为 DASH，不能作为完整文件默认；实况显式选择失效不能借新版本；ZIP 对已知大小核对实际字节，按真实 MIME 命名。

批量 ZIP 另复现了 deferred 条目首次解析成功、取字节失败后，重试会再次解析并跟随新默认的问题。归档任务现在立即在自己的私有快照中冻结已解析 item、variant 和 source，重试复用，不回写全局结果。回归确认解析仅一次、重试仍取原 URL、全局数据不变。普通实况主按钮同样复用已解析结果。

画质主列表恢复已确认的精简展示，同一实测分辨率收敛为一张卡，原始入口和不支持/待解析项单列；“全部版本”保留完整候选可达。展开、收回仅影响展示，不重新排序挑默认或更改显式来源。仅有合成夹具的部分不写成真实平台通过。
