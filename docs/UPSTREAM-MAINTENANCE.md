# 上游来源与维护方式

DokiTool 将 PHP 后端和 Vue 3/Vite 前端整合为一个独立维护的项目。初始代码采用下表中的指定快照，再进行本站接口和媒体行为适配；这个仓库不是 GitHub Fork，也不是两个上游仓库的完整镜像。上游的后续提交不会自动进入 DokiTool。

## 纳入范围

公开仓库收录可审查的源码、必要依赖声明、测试和通用维护文档。后端只纳入已注册解析路径及所需的类、共享运行代码和控制器：

- 六个公开 API：`/api/short_videos`、`/api/douyin`、`/api/ksjx`、`/api/bilibili`、`/api/xhsjx`、`/api/toutiao`。
- 聚合入口使用的九个平台：抖音、快手、B 站、小红书、头条、微博、皮皮虾、皮皮搞笑、最右。
- 路由依据是 `backend/lib/gateway.php`，新增平台必须同时审查其入口、依赖和测试，不能仅复制一个上游脚本后直接暴露。

不纳入真实 Cookie、账号凭据、令牌、私有环境文件或个人运行记录；空配置项和测试占位值不能被替换为真实凭据后提交。开放媒体代理、抖音主页 Cookie 入口、网易云 Python/Flask 服务、Workers 代理及其他未接入的可选入口，不属于当前整合范围。保留上游来源不等于必须导入全部文件、历史构建产物或可选服务。

当前适配包括同源 API 映射、显式选择加密协议、业务错误响应处理、B 站分 P 与懒解析行为修正，以及可达 PHP 请求的基础传输约束。后续采用上游更新时，需要保留并重新核对这些本项目行为。

## 人工采用上游更新

每次更新是一次有明确范围的代码变更，不是同步整个目录。维护者按以下步骤处理：

1. **选定目标提交。** 从 `UPSTREAM.json` 的已采用基线出发，阅读上游变更说明并比较到明确目标 SHA 的差异。记录要解决的问题、目标提交和拟采用的文件；不要把浮动分支名当作已核验版本。
2. **检查许可与内容。** 核对目标文件的许可证、版权声明、依赖变化和新增外部请求。检查示例 Cookie、令牌、代理地址、日志和环境文件，确保公开提交不包含秘密或无关服务。
3. **选择性移植。** 在本项目分支中按明确文件或代码片段移植改动，保留归属说明并适配本项目结构。审查者应能看到采用了什么、遗漏了什么、为何需要本地调整；不能用上游目录直接覆盖本地适配。
4. **审查接口与媒体行为。** 核对公开路由、固定内部请求目标、业务码和错误响应。检查图片、实况、备用直链、音乐、B 站分 P/合集及失败分 P 的行为，避免把缺失媒体误判为成功或回填成其他分 P。
5. **完成相称验证。** 运行受影响的 PHP 契约/语法检查、前端契约测试、类型检查和正式构建。修改聚合传输或路由时，补做本地 HTTP 验证；相关界面变化再验证浏览器行为。已通过且未受影响的检查不需要反复重跑。
6. **更新来源与发布记录。** 在采用的改动合并时记录对应上游提交、文件来源、许可证变化和验证范围。重新生成受影响的构建、许可声明与哈希清单；部分移植必须标明范围，不能声称已完整升级到整个上游版本。

本地 HTTP 测试使用独立的公开 PHP 测试入口和本地 mock 内部服务。进程核对、启动、健康检查、停止分别执行，测试服务只绑定 loopback。它验证 HTTP 请求和响应处理，不证明实际平台解析成功，也不能替代正式运行环境的联调；单进程 PHP 开发服务器不是生产运行方案。没有当前测试需要时，不启动可选服务或使用真实账号、Cookie、付费接口补充样例。

本项目不设置定时镜像任务，不自动拉取并覆盖上游文件，也不因上游出现新提交而自动发布。需要采用的新变化通过明确的改动范围、代码审查和验证进入本仓库。

GitHub Actions 每天北京时间 09:00 检查两上游的提交、Release 和标签，有变化时通过专用 Issue 通知。此任务只检测，不自动采用代码或部署；观察状态与本文件描述的已采用版本分开维护。运行方式、通知和调度限制见 [每日更新检查](UPSTREAM-WATCH.md)。
